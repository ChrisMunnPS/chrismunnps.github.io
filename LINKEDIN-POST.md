# LinkedIn launch post — SC-300 practice exam

## Primary post

I built something I wish I'd had when I started studying for SC-300.

Most practice exams give you a score and move on. I wanted one that tells me where I'm weak, why I got it wrong, and what to reread.

So I turned the Microsoft Learn SC-300 material into a full practice exam:

📚 110 scenario-style questions across all four domains
✅ 33 multi-select items, scored all-or-nothing like the real thing
🎲 A random 50-question exam by default, or choose your own question count
🎯 Section focus — drill identity, authentication, apps, or governance on their own
⏱️ Optional timer, or untimed practice with instant feedback
📊 A score report modelled on the Pearson VUE layout, with a per-section breakdown and a 700 pass marker
🔍 Full review: correct answer, your answer, why each distractor fails, and the Learn unit behind it
🎆 Fireworks when you pass
💾 Autosaves, so you can close the tab and come back later

It runs offline — plain HTML, CSS and JavaScript. No account, no telemetry, no cost. MIT licensed.

Repo: https://github.com/ChrisMunnPS/SC300Exam

It's unofficial and not affiliated with Microsoft, but every question maps back to the SC-300T00 modules, so a wrong answer always has a next step.

If you're working toward SC-300: which domain would you drill first — identity, authentication, apps, or governance?

## Posting notes

- **Push the files first.** The repo currently contains only `README.md` and `LICENSE`; the link will look empty until `exam-sim/` and the four Markdown documents are committed.
- **Attach an image.** A screenshot of the score report (results screen) or the start screen will stop the scroll better than a text-only post. LinkedIn treats native image posts more favourably.
- **Links in the post are fine.** This is a resource people will want to save; do not bury it in the comments.
- **If you enable GitHub Pages,** use the live URL as the main link and keep the repo link in the first comment. Publishing the `exam-sim/` folder at the site root is the fastest route.
- **Reply fast.** Early comments decide reach. Answer the "which domain" question with your own weakest domain and what you changed in your study plan.
- **Consider a follow-up post** with one worked question (stem, options, explanation) to show the quality of the reasoning rather than just the feature list.
