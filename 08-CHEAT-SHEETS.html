SC-300 cheat sheet 1/4 — Implement and manage user identities

One page. Facts snapshot 2026-11; verify current behavior on Microsoft Learn before the exam.

Tenant, domains, and directory data

ItemWhat to remember
Initial domainEvery tenant starts with <name>.onmicrosoft.com. It cannot be removed or renamed.
Custom domainAdd the DNS name, prove ownership with a TXT (or MX) record, then set it as primary. A domain can be verified in only one tenant at a time.
Tenant identityThe tenant ID (GUID) is stable; the primary domain can change. Apps and scripts should use the tenant ID.
Directory roles vs Azure RBACEntra roles govern directory objects; Azure RBAC governs Azure resources. Global Administrator can elevate access to gain User Access Administrator at the root management scope.
Administrative unitsScope a role (for example User Administrator) to a subset of users, groups, or devices. Good for regional helpdesk delegation.
Role-assignable groupsA security group can hold Entra roles, but the group must be created with isAssignableToRole = true; membership then grants the role.
Protected actionsHigh-impact actions can require a Conditional Access authentication context. The role assignment alone is not enough.

Tenant-wide settings and branding

ItemWhat to remember
Company brandingNeeds Entra ID P1/P2 or Office 365. Language is set automatically and can't be changed; background image max 1920x1080 and 300,000 bytes; username hint ≤64 chars; sign-in text ≤1,024 chars.
Tenant propertiesDirectory name, country/region, notification language, tenant ID, technical contact, global privacy contact, and privacy statement URL.
User and guest settingsUser settings control app registration, profile edits, password changes, and portal access. Application Developer restores app registration; Directory Readers restores portal access. External collaboration controls guest access, guest invites, and guest self-service.

Users, groups, and licensing

ItemWhat to remember
User typesMember (in the tenant) vs Guest (B2B). userType is informational; authorization comes from assignments.
Bulk operationsBulk create/invite/delete use a CSV template. Errors are reported per row; a failed row does not stop the rest.
Dynamic groupsRule-based membership, for example user.department -eq "Sales" -and user.accountEnabled -eq true. Membership is read-only; you cannot manually add or remove members.
Assigned vs dynamicAssigned groups take manual members. Dynamic user groups evaluate user attributes; dynamic device groups evaluate device attributes.
Security vs Microsoft 365Security groups grant access only. Microsoft 365 groups add a shared mailbox, calendar, Teams, and SharePoint site.
Nested groupsGroup-based licensing does not flow through nested groups, and dynamic groups cannot contain groups as members. Flatten membership for licensing.
Group-based licensingAssign one or more licenses to a group. Every direct member gets the license; removing a member removes it. Requires a usage location on each user.
Licensing errorsCommon failures: not enough licenses, usage location not set, conflicting service plans, and mutually exclusive plans. Re-process after fixing the cause.
Soft deleteDeleted users, Microsoft 365 groups, cloud security groups, app registrations, and service principals stay restorable for 30 days with the same object ID.
Hard deletion protectionPreview. Blocks permanent deletion for 7 days after each soft delete; restoring keeps protection, and deleting the object again restarts the window. Covers cloud-only users, groups, applications, and service principals. Permanent once enabled; soft deletion still succeeds. Needs the Entra Backup Administrator role.
After 30 daysThe object is hard deleted. It cannot be restored; recreate and reconfigure it.

External identities and hybrid identity

ItemWhat to remember
B2B collaborationInvite an external user; Entra creates a guest object in your tenant. The guest redeems the invitation and authenticates in their home tenant. Control with cross-tenant access settings and external collaboration settings.
B2B direct connectNo guest object. Used for Teams shared channels; access is controlled by cross-tenant access policy.
B2B authentication trustYou can trust MFA and compliant-device claims from another Entra tenant so guests are not forced to register again.
Tenant restrictions v2Configured in cross-tenant access settings, replacing proxy allow lists. Allow/block named external tenants for internal identities and block external identities entirely. Enforced by Global Secure Access universal tenant restrictions tagging, needing GSA Administrator + Security Administrator. Data plane protection blocks token replay against Microsoft Graph and anonymous SharePoint access.
Azure AD B2CSeparate tenant and directory for customer identities. Supports local accounts, social IdPs, custom policies, and branded sign-in. Do not confuse with B2B.
Entra Connect SyncRich sync engine for hybrid identity. Supports password hash sync (PHS), pass-through authentication (PTA), and federation with AD FS, plus attribute transforms, filtering, and writeback.
Cloud SyncLightweight agent-based sync, primarily PHS with a smaller feature set. Good for multi-forest and simple topologies; it does not replace every Connect Sync feature.
Seamless SSOKerberos-based desktop SSO for domain-joined PCs. Users sign in to Entra without retyping the corporate password. Requires the Seamless SSO computer account and client configuration.
Password writebackEnables cloud SSPR and password changes to write back to on-premises AD. Configure it in the sync client; without it, cloud reset does not change the on-prem password.
Staging modeA Connect Sync server in staging mode imports and syncs but does not export. Use it to validate a replacement server before cutover.
Connect HealthAgents report sync, AD FS, and health data to Entra. Use alerts to catch export errors, stale sync, and agent failures.
FilteringScope sync by OU, domain, or attribute. Filtering is not security: excluded objects can still exist in the cloud if they were synced before.

High-yield exam traps

  • Deleting and recreating a group or app creates a new object ID; existing assignments and Conditional Access references break.
  • A deleted group can be restored only during the 30-day window; after that, rebuild it.
  • Hard deletion protection blocks the hard delete, not the initial soft delete, and cannot be turned off.
  • Global Administrator does not automatically grant Azure subscription access until access is elevated.
  • Group-based licensing ignores nested group members.
  • Cloud Sync is not a drop-in replacement for every Connect Sync feature; check PTA/federation and writeback requirements first.

SC-300 cheat sheet 2/4 — Implement authentication and access management

One page. Facts snapshot 2026-11; verify current behavior on Microsoft Learn before the exam.

Authentication methods

MethodKey facts
PasswordSomething you know. Strengthen with banned-password lists, smart lockout, and MFA.
Microsoft AuthenticatorPush approval or passwordless phone sign-in. Supports number matching and additional context to defeat MFA fatigue.
FIDO2 security keyPhishing-resistant, passwordless, hardware-bound credential. Register per user; can be shared only with a shared-device design.
Passkey (FIDO2) profilePer-group policy. Attestation is checked only at registration (synced passkeys fail); AAGUID lists apply at registration and every sign-in, so removing one blocks keys. Needs Authentication Policy Administrator.
Windows Hello for BusinessPhishing-resistant, device-bound PIN/biometric. Best with Entra join or hybrid join; supports key trust and certificate trust.
Certificate-based auth (CBA)Phishing-resistant PKI credential, often on smart cards. Requires certificate trust and issuance rules.
Kerberos SSO (App Proxy)Application Proxy uses Kerberos Constrained Delegation (KCD) for IWA apps. Connectors must be domain-joined with AD rights to impersonate users and read TokenGroupsGlobalAndUniversal.
Temporary Access Pass (TAP)Time-limited passcode for onboarding, device setup, and recovery. Lifetime 10 min to 30 days; one valid pass per user; shown once; single- or multi-use. Satisfies MFA, not phishing-resistant. Needs P1/P2.
OATH tokensTOTP/HOTP hardware or software tokens. Seed files import into Entra; users enter the 6-digit code.
SMS / voiceConvenient but weaker; avoid for administrators and high-risk users. Availability depends on the authentication methods policy.
Email OTP / security questionsEmail OTP is for B2B guest redemption, not general member MFA. Security questions are SSPR only and not allowed for administrators.

MFA, SSPR, and password protection

ItemWhat to remember
Per-user MFA vs Conditional AccessPer-user MFA is legacy and always-on. Conditional Access is the modern, granular control and requires Entra ID P1.
Authentication methods policyOne policy controls which methods are enabled and which targets (all users, specific groups). Migration from legacy MFA settings matters.
Authentication strengthsPresets such as MFA, passwordless MFA, and phishing-resistant MFA. Use in CA grant controls to require a class of method, not one specific method.
SSPR scopeNone, Selected (one group), or All. Users need two methods to reset. Administrators need two strong methods; security questions are not allowed for admins.
SSPR writebackRequired for hybrid users. Without password writeback, the on-prem AD password is not updated.
Combined registrationUsers register MFA and SSPR methods in one flow. Enable it to avoid duplicate registration prompts.
Password protectionGlobal banned password list plus an optional custom banned list of up to 1,000 terms. On-prem AD needs the Password Protection proxy and DC agents.
Smart lockoutLocks an account after repeated bad passwords. Default threshold 10 attempts, default duration 60 seconds; configurable.
Identity ProtectionRequires P2. Detects user risk and sign-in risk; policies can require password change or MFA, or block.
Risk policiesUser risk policy remediates compromised credentials; sign-in risk policy challenges suspicious sign-ins. Both can be report-only.
MFA registration policyIdentity Protection policy that forces users to register MFA. Applies to all users by default; exclude emergency access accounts.
Workload identity riskRequires P2. Covers single-tenant service principals; third-party SaaS, multitenant apps, and managed identities are out of scope. Detections include leaked credentials, unusual OAuth credential additions, and suspicious sign-ins baselined over 2–60 days.
Identity Risk Management AgentRequires P2 plus SCUs. Security Administrator acts; Security Reader and Global Reader view only. Runs every 5 min, daily, or manually; default scope = last 100 risky users in 90 days.
Microsoft Defender for IdentityOn-prem AD detection. Sensors run on domain controllers (no port mirroring) and AD FS; managed in the Defender portal (security.microsoft.com).

Conditional Access and session control

ItemWhat to remember
LicenseEntra ID P1 per user for CA policies. P2 adds risk-based conditions from Identity Protection.
AssignmentsInclude/exclude users, groups, workload identities, and cloud apps or actions. Exclude emergency-access accounts from every policy.
ConditionsDevice platform, location/named locations, client apps, sign-in risk, user risk, authentication flows, device state/filters, and insider risk.
Grant controlsBlock, require MFA, require compliant or hybrid-joined device, require app protection policy, require authentication strength, require terms of use, or require a custom control.
Session controlsSign-in frequency, persistent browser session, app-enforced restrictions, continuous access evaluation (CAE), and token protection.
Report-only modeEvaluates a policy and reports what would happen without enforcing it. Use it before rollout.
Policy evaluationAll applicable policies must pass. A single block wins; exclusions are evaluated before controls.
Named locationsDefine trusted IP ranges or countries. Do not treat a country block as a substitute for strong authentication.
Emergency access accountsAt least two cloud-only accounts with permanent Global Administrator, excluded from CA, MFA, and SSPR; monitor their use.
Sign-in frequencyReauthentication interval for a user or app. Separate from token lifetime; CAE can revoke tokens in near real time.
Global Secure AccessInternet/Private Access route traffic through Microsoft's security edge. Remote networks: IPsec from a branch CPE router, clientless. Traffic logs: session → connection → transaction; Microsoft 365 logs use OfficeActivity + NetworkAccessTraffic, SharePoint Online only. Compliant network needs GSA signaling for Conditional Access; Microsoft 365 enforces only with the GSA client, not a remote network.
CA optimization agentSecurity Copilot agent that finds unprotected users, blocks legacy auth and device code flow, and consolidates policies. Needs P1, SCUs, Security Administrator; device controls need Intune.

High-yield exam traps

  • CA policies require P1; risk conditions and Identity Protection require P2.
  • "Require MFA" is not the same as "require phishing-resistant MFA". Use authentication strengths.
  • SSPR cannot write a password back to on-prem AD without password writeback enabled.
  • Administrators cannot use security questions for SSPR and must register two methods.
  • Report-only mode does not block anything, even when the policy would deny access.
  • Do not lock yourself out: exclude emergency access accounts and validate with report-only first.
  • Number matching and additional context reduce MFA push fatigue; they do not make push phishing-resistant.

SC-300 cheat sheet 3/4 — Plan and implement workload identities

One page. Facts snapshot 2026-11; verify current behavior on Microsoft Learn before the exam.

Objects and consent

ItemWhat to remember
App registrationThe application definition in your tenant: client ID, redirect URIs, credentials, API permissions, app roles, manifest, owners.
Enterprise applicationThe service principal (instance) of an app in a tenant. Controls assignments, SSO, provisioning, and user-visible properties.
Single vs multi-tenantSingle-tenant apps accept only accounts from the home tenant. Multi-tenant apps use the common (or tenant-specific) endpoint and require consent in each tenant.
Delegated permissionApp acts as the signed-in user. Requires user or admin consent; effective access is the intersection of user rights and granted scopes.
Application permissionApp acts as itself, no signed-in user. Always requires admin consent; often needs a client secret or certificate.
Admin consent workflowUsers request consent; designated reviewers approve in the Entra admin center. Configure under Enterprise applications > Consent and permissions.
User consent settingsOptions: disable user consent, verified publishers + chosen low-impact permissions, all apps, or a custom app consent policy. Risk-based step-up consent is on by default and sends risky requests to admin approval; without the admin consent workflow the user sees AADSTS90094 and the audit shows ApplicationManagement / Consent to application / Risky application detected.
Token customizationToken lifetime policies set access/ID token, refresh token, and sliding-window lifetimes for all apps, a multitenant app, or one service principal. Optional claims add or change claims per app and matter most moving from v1.0 to v2.0 tokens.
Redirect URIMust exactly match the app's configured reply URL. Prefer the authorization code flow with PKCE for public clients.
CredentialsClient secrets are strings with expiry; certificates are stronger. Store secrets in Key Vault and rotate before expiry.
App roles vs groupsApp roles are defined in the app manifest and assigned to users/groups. Group claims can also carry membership, but large groups require a token-size strategy.

Single sign-on and app proxy

ItemWhat to remember
SAML SSOConfigure Identifier (Entity ID), Reply URL (ACS URL), and Sign-on URL in Entra and the app. Exchange the signing certificate and map claims (NameID, email, groups).
SAML certificatesEntra signs SAML assertions/responses with a certificate. Plan rollover: download the new certificate, update the app, then activate.
NameIDChoose a stable, unique claim such as UPN or object ID. Changing the NameID format can break existing app accounts.
OIDC / OAuth 2.0Use discovery metadata, client ID/secret, scopes, and redirect URIs. ID tokens identify the user; access tokens authorize APIs.
Password-based SSOEntra stores credentials and replays them through the My Apps browser extension. Use for legacy apps with no modern protocol.
Linked SSOEntra simply links to an existing app URL. No sign-in brokering.
Application ProxyPublishes on-premises apps without a VPN. A connector runs on a server inside the network and makes outbound connections only.
App Proxy pre-authenticationChoose Entra ID pre-auth (CA, MFA, conditional access) or passthrough. Entra ID pre-auth is the secure default.
Kerberos delegationFor Windows integrated auth, configure Kerberos constrained delegation (KCD) on the connector's service account and the app's service principal name.
Custom domainsApp Proxy can use a verified custom domain and certificate instead of the default msappproxy.net URL.
Header-based SSOApp Proxy can inject identity headers for legacy apps that cannot use SAML/OIDC.

Provisioning, identities, and app governance

ItemWhat to remember
SCIM provisioningAutomates user/group create, update, and disable in SaaS apps. Map attributes with expressions; use provisioning logs to debug.
Attribute mappingsMatch by a unique attribute (often userPrincipalName or mail). Test with a single user before turning on the full sync.
DeprovisioningOn unassignment or user deletion, provisioning can disable or delete the app account. Configure the behavior deliberately.
Assignment requiredEnterprise app setting that blocks sign-in unless the user or group is assigned. Pair it with group-based assignment.
Managed identityAzure-managed service principal with no secret to manage. System-assigned dies with the resource; user-assigned can be shared across resources.
Workload identity federationReplace secrets with a trust relationship between an external workload (GitHub, Kubernetes, Azure DevOps) and an app registration or managed identity.
Service principal vs managed identityBoth are identities; a managed identity is a special service principal tied to an Azure resource and cannot be configured with a client secret.
App governanceDefender for Cloud Apps add-on for OAuth apps using Microsoft Graph to reach Microsoft 365 data. Provides insights, governance policies, detection, and automatic remediation. Enable under Settings > Threat Protection > App Governance.
OAuth app policiesIn Defender for Cloud Apps > Cloud apps > OAuth apps, create a permission policy to alert on high-permission apps authorized by many users, ban a permission (which disables the enterprise app), or scope by the group membership of users who consented. The Community use filter flags rare permissions.
Cloud Discovery and CASBDefender for Cloud Apps is Microsoft's CASB. Cloud Discovery reads firewall/proxy traffic logs to find shadow IT; the Cloud app catalog rates 16,000+ apps on 80+ risk factors. Sanction or unsanction apps from the catalog.
Application collectionsRequires P1/P2. Group related apps into tabs for users in My Apps; a collection only shows apps the user is already assigned. Admins create them under Enterprise applications > App Launchers > New collection; users can create personal collections.
Restore deleted appsApp registrations and service principals are restorable for 30 days from Deleted applications. The same client ID, permissions, and assignments return.
Hard deletion protectionCan protect cloud applications and service principals from permanent deletion for seven days after each soft delete; restoring keeps protection and a new delete restarts the window. Preview feature, permanent once enabled, needs the Entra Backup Administrator role.

High-yield exam traps

  • An enterprise app is not a second registration; it is the service principal of the app in the tenant.
  • Delegated permission acts as the user; application permission acts as the app and needs admin consent.
  • A new app registration means a new client ID; recreating an app breaks existing consent, tokens, and assignments.
  • SAML failures usually come from an ACS/entity ID mismatch, expired certificate, or NameID format change.
  • App Proxy connectors need outbound access only; do not open inbound firewall ports.
  • User consent disabled does not revoke existing grants; review existing permissions separately.
  • Restoring only the service principal does not restore a deleted app registration, and vice versa.

SC-300 cheat sheet 4/4 — Plan and automate identity governance

One page. Facts snapshot 2026-11; verify current behavior on Microsoft Learn before the exam.

Entitlement management

ItemWhat to remember
CatalogContainer of resources (groups, applications, SharePoint sites) and access packages. Delegate catalog owners and readers.
Access packageA bundle of resources that fulfills a role or project. Users request the package rather than individual resources.
Assignment policyDefines who can request (users/groups/connected organizations), approval, expiration, access review, and whether assignment is direct or auto-assigned.
Multiple policiesOne package can have several policies with different audiences, approval, and lifetime. Users request the package and match a policy.
ApprovalOptional single- or multi-stage approval. Delegated approvers can be managers, group owners, or specific users.
ExpirationAssignments can expire after a number of days, on a date, or never. Expired access must be re-requested.
External usersConnected organizations define partner tenants or domains. External users receive guest objects; lifecycle removes access when the package expires.
Separation of dutiesIncompatible access packages can block a user from holding conflicting access. Evaluate at request time.
Per-user entitlementsOpen an access package's Assignments to see each user, policy, and status. Filter Delivering for provisioning errors or Expired, and Download a CSV. Roles: Identity Governance Administrator, User Administrator, Catalog owner, Access package manager, or Assignment manager.
LicenseEntra ID P2 (or Entra ID Governance) for entitlement management.

Access reviews

ItemWhat to remember
ScopeGroup membership, app assignment, Entra role assignment, Azure resource role, or access package assignment.
ReviewersResource owner, group owner, selected users, managers, or self-review. Define a fallback if reviewers do not respond.
RecurrenceOne-time, weekly, monthly, quarterly, semi-annual, or annual. Set duration and whether reviewers must justify.
DecisionsApprove, deny, or don't know. Auto-apply applies results when the review ends; without it, decisions do not change access.
Recommendations"Inactive users" recommendations flag users with no sign-in in the last 30 days. Use as input, not as the only decision.
Access Review AgentNeeds Entra ID Governance or Entra Suite + Security Copilot (1 SCU). Recommends approve/deny with justification in Teams from a score of inactivity, affiliation, account enabled, leaver date, mover workflow, prior decisions, and request history. Reviewers need Security Copilot Contributor; once started it cannot be paused.
Guest reviewsReview guest access separately; denied guests can be removed from the group, app, or tenant.
Role reviewsReview privileged role assignments (PIM eligible and active) on a recurring basis to enforce least privilege.
LicenseEntra ID P2 / Entra ID Governance.

Privileged Identity Management (PIM)

ItemWhat to remember
Eligible vs activeEligible means the user can activate the role on demand. Active means the role is assigned permanently or for a fixed period.
Activation requirementsMaximum duration, MFA, justification, ticket information, and approval. Configure per role in role settings.
Default durationEntra role activation default is 8 hours; role settings can shorten or lengthen it. Azure resource roles have their own settings.
ApprovalDesignate approvers. The request waits until approved; the user cannot use the role before activation completes.
NotificationsPIM alerts for too many Global Administrators, roles assigned outside PIM, stale assignments, and activation anomalies.
PIM for groupsMakes group membership eligible or active with activation and approval. Requires the group to be onboarded to PIM.
PIM audit historyResource audit shows all activity for a privileged access group; My audit shows only your own role activity. Filter by predefined or custom dates. Assignments made through Azure delegated resource management are excluded.
PIM for Azure resourcesJust-in-time access to Azure RBAC roles at management group, subscription, resource group, or resource scope.
Access reviews for PIMRecurring review of eligible/active assignments; remove assignments that are no longer justified.
Emergency access accountsKeep two permanent Global Administrator accounts excluded from PIM and CA. Monitor sign-ins and alert on use.
LicenseEntra ID P2 / Entra ID Governance (PIM for groups and Azure resources included).

Lifecycle workflows and monitoring

ItemWhat to remember
Lifecycle workflowsAutomate joiner, mover, and leaver tasks. Triggers include on-demand, scheduled, attribute changes, and group membership changes.
TasksEnable/disable account, add/remove group, send email, generate TAP, run a custom extension (Logic Apps).
ScopeA workflow runs against a scope (all users or a group) and a trigger condition. Test with a small scope first.
Custom extensionsCall an Azure Logic App from a workflow for tasks the built-in tasks do not cover.
Audit and sign-in logsAudit records who changed what, filterable by service, category, activity, status, target, and initiator; download CSV/JSON up to 250,000 records. Sign-ins covers interactive sign-ins only, can lag up to 2 hours, and is readable by Security/Global/Report readers and each user. Retained 30 days; export for longer.
Provisioning logsRecords SCIM create/update/disable actions and failures. Use them to debug attribute mappings.
Diagnostic settings and SentinelStream audit, sign-in, provisioning, and risk logs to Log Analytics, storage, or Event Hub. Sentinel is cloud SIEM and SOAR; sign-in ingestion needs P1/P2, access needs Sentinel Contributor + Security Administrator. A workspace holds 730 days interactive and 12 years total; Entra's 30-day store cannot meet a multi-year rule.
Workbooks and Identity Secure ScoreWorkbooks summarize access, reviews, and PIM. Identity Secure Score is a percentage in all editions, scored binary or proportionally, with industry comparison and trend.
Terms of useRequire acceptance with a Conditional Access grant control. Acceptance is recorded per user and version.

High-yield exam traps

  • Entitlement management and access reviews need P2; do not propose them with P1 only.
  • An access review does not change access unless auto-apply is enabled.
  • PIM eligible assignment is not active access; the user must activate and satisfy approval/MFA.
  • Access package expiration and access review are different controls; use both for time-bound, validated access.
  • Deleting a group does not remove the business need for access; use access packages and reviews to prevent entitlement sprawl.
  • Audit retention is limited; export logs if the investigation window is longer than 30 days.
  • Review guest access and privileged roles on a different cadence from standard group membership.
